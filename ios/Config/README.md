# ios/Config

Build configuration that XcodeGen reads or writes. Nothing in this folder is compiled into the app.

| File | In git? | What it is |
|---|---|---|
| `Signing.xcconfig` | yes | Bundle identifier (`com.nexafix.scan`) for the app target. Ends with `#include? "Local.xcconfig"`. |
| `Local.xcconfig` | no (ignored) | Your own `DEVELOPMENT_TEAM` and, if the default is taken, your own `PRODUCT_BUNDLE_IDENTIFIER`. Create it with `ios/tools/remember-signing.sh` or from `Local.xcconfig.example`. Survives `xcodegen generate` and `git pull`. |
| `Local.xcconfig.example` | yes | Template for the above. |
| `Info.plist` | no (ignored) | Generated by `xcodegen generate` from `info:` in `project.yml`. Edit `project.yml`, not this file. |

This folder is tracked so that it exists on a fresh clone (XcodeGen writes `Info.plist` into it).

## Privacy manifest (`../NexaFixScan/Resources/PrivacyInfo.xcprivacy`)

The manifest has no comments on purpose (plain XML property list). What it declares and why, checked against
Apple's "Describing use of required reason API" and by `ios/tools/preflight.py`, which scans the Swift sources:

| Category | Reason | Used by |
|---|---|---|
| `NSPrivacyAccessedAPICategoryUserDefaults` | `CA92.1` (data only this app reads) | `AppSettings` (units, haptics, plan scale, paper), `ExportSheet` (last chosen formats) |
| `NSPrivacyAccessedAPICategorySystemBootTime` | `35F9.1` (time elapsed between events inside the app) | `ProcessInfo.systemUptime` in `ScanSessionController.now()` for debounce and relocalisation timeouts |

Not declared because the code does not call them: file timestamp APIs (`creationDate`, `modificationDate`,
`contentModificationDateKey`, `stat` ...), disk space APIs (`volumeAvailableCapacity...`, `statfs`,
`systemFreeSize` ...), active keyboards. If you add one, add its category and a reason from Apple's list, or
`preflight.py` fails. No data is collected and nothing is tracked.
